# ADR-006. Python и Django

## Контекст

Нужен фреймворк для модульного монолита (ADR-001) со страницами, формируемыми сервером (ADR-003), и
PostgreSQL (ADR-002). Из требований нужны:

- вход с паролем, сессии, защита форм, хранение хешей паролей (НФТ-02);
- права по ролям на каждом запросе (НФТ-01);
- проверка форм с сообщениями на русском (ФТ-27, НФТ-10);
- транзакции, блокировки строк, миграции схемы (ФТ-12, ФТ-16, НФТ-07);
- чтение и запись .xlsx (ФТ-06, ФТ-26, ФТ-30), штрихкод Code 128 (ФТ-29).

## Рассмотренные варианты

1. **Python 3.12, Django 5.2 LTS.**
2. **Java 21, Spring Boot 3.**
3. **Node.js, NestJS** с отдельным шаблонизатором.

| Критерий | Django | Spring Boot | NestJS |
|---|---|---|---|
| Вход, сессии, CSRF, хеши паролей | Встроены | Spring Security, настройка | Отдельные библиотеки |
| Формы с проверкой и русскими сообщениями | Встроены, локализация есть | Bean Validation и шаблоны | Отдельные библиотеки |
| ORM, миграции, `select_for_update` | Встроены | JPA, Flyway, есть | TypeORM или Prisma, есть |
| Excel, Code 128 | openpyxl, python-barcode | Apache POI, ZXing | ExcelJS, bwip-js |
| Срок поддержки версии | 5.2 LTS – до апреля 2028 | 3.x – по графику Spring | По графику Node.js LTS |
| Объём кода для форм и списков | Наименьший | Больше | Больше |

## Выбранное решение

Python 3.12 и Django 5.2 LTS; веб-сервер – gunicorn за nginx. Библиотеки: openpyxl (Excel), python-barcode
(Code 128 в SVG), argon2-cffi (хеши паролей), import-linter (проверка границ модулей, П-01). Каждый модуль
архитектуры – приложение Django со своими моделями и файлом функций, через которые его вызывают другие
модули.

## Причины выбора

- Вход, сессии, CSRF, формы и миграции встроены – меньше собственного кода в частях, связанных с
  безопасностью.
- Приложения Django естественно соответствуют модулям ADR-001.
- Версия с долгосрочной поддержкой покрывает срок разработки и первые годы эксплуатации.

## Последствия

- Для сопровождения нужен разработчик Python; на сервер ставится Python 3.12.
- Python медленнее Java на вычислениях, но запросы АС УВО упираются в базу данных, а не в процессор:
  нагрузка 1000 пользователей покрывается несколькими процессами gunicorn (architecture.md, раздел 6).
- До апреля 2028 года систему нужно перевести на следующую версию Django с долгосрочной поддержкой.

## Риски

| Риск | Мера |
|---|---|
| Уязвимость в зависимостях | Зафиксированные версии, проверка pip-audit при сборке, установка исправлений Django |
| Окончание поддержки Django 5.2 | Плановый переход на следующую LTS до апреля 2028 |
